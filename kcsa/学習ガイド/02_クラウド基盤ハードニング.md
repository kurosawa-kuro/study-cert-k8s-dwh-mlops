# クラウド基盤ハードニング — ウェブエンジニア向け実践ガイド

> **対象:** ウェブエンジニア（SQLインジェクション等の基礎セキュリティ知識あり）が KCSA 対策で押さえるべき **AWS 基盤セキュリティ** の要点
> **範囲:** IAM 最小権限 / VPC PrivateLink / CloudTrail + IAM Policy Simulator による過剰権限検出
> **目標:** ウェブアプリケーションのクラウドインフラセキュリティを理解し、k8s クラスタの基盤保護を実装

## 1. A4 図解：3 本柱と相互関係（攻撃者視点）

```
┌──────────────────────────────────────────────┐
│                IAM (Identity)               │
│  ── 攻撃ベクトル: 権限奪取・認証情報漏洩・権限昇格    │
│  ── 防御策: Principle of Least Privilege    │
│  ── 実装: IAM Roles / Policies / SCP        │
└──────────────────────────────────────────────┘
            ↓  attaches permissions      ↑ simulate
┌──────────────────────────────────────────────┐
│         Network Segmentation (VPC)           │
│  ── 攻撃ベクトル: ネットワーク侵入・データ漏洩・DDoS    │
│  ── 防御策: Private Subnet / Security Group  │
│  ── 実装: VPC Endpoint & PrivateLink         │
└──────────────────────────────────────────────┘
            ↓  logs API calls                 ↑ informs
┌──────────────────────────────────────────────┐
│               Audit & Monitoring             │
│  ── 攻撃ベクトル: ログ改ざん・監査回避・異常検知漏れ    │
│  ── 防御策: CloudTrail (Org‑Trail) + S3 Log  │
│  ── 実装: EventBridge + Security Hub         │
└──────────────────────────────────────────────┘
```

| ---------- | ------------------------------------------------------------------------------- | ----------------------------------------------- |

## 3. Hands‑on ラボ（30 分）

### 3.1 IAM 最小権限ロールの作成 & シミュレーション

```bash
# (1) 最小権限ポリシーを JSON で用意（WebアプリのDB接続例）
cat <<'EOF' > webappDbAccess.json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": [
      "rds:DescribeDBInstances",
      "rds:DescribeDBClusters",
      "secretsmanager:GetSecretValue"
    ],
    "Resource": [
      "arn:aws:rds:ap-northeast-1:*:db:webapp-db",
      "arn:aws:secretsmanager:ap-northeast-1:*:secret:db-credentials"
    ]
  }]
}
EOF
aws iam create-policy --policy-name WebAppDbAccess --policy-document file://webappDbAccess.json

# (2) ロールへアタッチ
aws iam create-role --role-name WebAppService \
  --assume-role-policy-document file://<(aws iam get-policy-version \
     --policy-arn arn:aws:iam::aws:policy/ServiceRolePolicy --version-id v1 | jq .PolicyVersion.Document)
aws iam attach-role-policy --role-name WebAppService --policy-arn arn:aws:iam::<ACCOUNT_ID>:policy/WebAppDbAccess

# (3) Policy Simulator で検証 (CLI)
aws iam simulate-principal-policy --policy-source-arn arn:aws:iam::<ACCOUNT_ID>:role/WebAppService \
  --action-names rds:DeleteDBInstance
# ↑ Should return "Decision": "implicitDeny"
```

### 3.2 VPC PrivateLink で API 通信を内部化

```bash
# パブリック S3 → Interface Endpoint 例（Webアプリの静的ファイル配信）
aws ec2 create-vpc-endpoint --vpc-id vpc-xxxx \
  --service-name com.amazonaws.ap-northeast-1.s3 \
  --vpc-endpoint-type Gateway --route-table-ids rtb-xxxx
```

### 3.3 CloudTrail 組織トレイルの有効化

```bash
aws cloudtrail create-trail --name org-trail \
  --is-organization-trail --s3-bucket-name org-trail-logs-<ACCOUNT_ID> \
  --kms-key-id alias/org-trail-key
aws cloudtrail start-logging --name org-trail
```

> **確認:** GuardDuty や Security Hub を有効化し、CloudTrail イベントを統合して異常検知のシグナルを増幅。
