# Container Runtime Protection 基礎 — seccomp・AppArmor・rootless

> **対象:** CKAD 85 %・Killer.sh 70 % レベルのエンジニアが KCSA 試験に向けて押さえる **コンテナランタイム保護** の必須ポイント
> **範囲:** seccomp / AppArmor / rootless コンテナ
> **キーワード:** DefaultProfile・RuntimeClass・`--security-opt seccomp=...`

---

## 1. コンテナ実行フローと保護ポイント

```
         kubectl                 CRI (containerd)          Kernel
┌──────────────┐   OCI spec   ┌─────────────────┐   seccomp / AppArmor
│  API Server  │────────────▶│  runc / crun     │───────────▶│  Syscalls  │
└──────────────┘              └─────────────────┘             └───────────┘
         ▲                            │  Namespace / cgroups / rootless
         │ RuntimeClass               ▼
   PodSpec.securityContext   <default profiles or custom>
```

---

## 2. 1 行ベストプラクティス

| カテゴリ             | ベストプラクティス                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------- |
| **seccomp**      | *`seccompProfile: { type: RuntimeDefault }` を全 Pod に強制し、必要に応じて最小許可のカスタム JSON を適用*           |
| **AppArmor**     | *Ubuntu 系 Node では `localhost/` プレフィックスでプロファイルを load し、Pod Annotation で紐付け*                  |
| **rootless**     | *`runAsNonRoot: true` & non‑0 UID を設定し、可能なら **rootless containerd** / **userns‑remap** を採用* |
| **RuntimeClass** | *gVisor / Kata など Sandbox Runtime を高感度ワークロードに適用し、Pod 単位で分離強化*                               |

## 3. Hands‑on ラボ（20 分）

### 3.1 seccomp — デフォルト → カスタム

```bash
# 0) kind クラスタ (v1.29+) は RuntimeDefault が有効。確認:
kubectl run nginx --image=nginx --restart=Never --dry-run=client -o yaml \
  | yq '.spec.securityContext.seccompProfile'
# => {type: RuntimeDefault}

# 1) 特権システムコール (e.g. ptrace) を deny するカスタム profile
cat <<'JSON' > deny-ptrace.json
{
  "defaultAction": "SCMP_ACT_ERRNO",
  "syscalls": [
    { "names": [ "ptrace" ], "action": "SCMP_ACT_ERRNO" }
  ]
}
JSON

# 2) Pod で適用 (hostPath でマウント)
cat <<'EOF' | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: demo-seccomp
spec:
  securityContext:
    seccompProfile:
      type: Localhost
      localhostProfile: deny-ptrace.json
  volumes:
  - name: prof
    hostPath: { path: /var/lib/kubelet/seccomp }
  containers:
  - name: bx
    image: busybox
    command: ["sh", "-c", "sleep 3600"]
    volumeMounts:
    - name: prof
      mountPath: /var/lib/kubelet/seccomp
EOF
# Pod 内で strace → Operation not permitted を確認
```

> **簡易確認:** `kubectl run test --rm -it --image=busybox --seccomp localhost/deny-ptrace.json sh` でも可。

### 3.2 AppArmor プロファイル適用（Ubuntu Node 例）

```bash
# 1) プロファイル作成
cat <<'EOF' | sudo tee /etc/apparmor.d/container-deny-mount
profile container-deny-mount flags=(attach_disconnected,mediate_deleted) {
  abi <abi/3.0>,
  deny mount,
}
EOF
sudo apparmor_parser -r /etc/apparmor.d/container-deny-mount

# 2) Pod に Annotation で紐付け
kubectl run apparmor-demo --image=busybox --restart=Never \
  --overrides '{"apiVersion":"v1","metadata":{"annotations":{"container.apparmor.security.beta.kubernetes.io/apparmor-demo":"localhost/container-deny-mount"}}}'
```

### 3.3 rootless コンテナ & RuntimeClass

```bash
# PodSpec 例: non‑root ユーザ + Kata runtime
cat <<'EOF' | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: rootless-kata
spec:
  runtimeClassName: kata-containers
  securityContext:
    runAsUser: 1000
    runAsNonRoot: true
  containers:
  - name: app
    image: busybox
    command: ["id"]
EOF
```
