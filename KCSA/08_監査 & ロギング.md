> **対象:** CKAD 85 %・Killer.sh 70 % のスキルを持つエンジニアが KCSA 試験対策として習得すべき “監査 & ロギング” の必須トピック。
> **範囲:** Audit Policy 設定 / Fluent Bit 集約 / `kubectl exec` イベント検証
> **キーワード:** `audit-policy.yaml`・AuditSink・Fluent Bit・Loki / Elasticsearch

                                                      └──────────────┘  └─────────────┘

## 2. 1 行ベストプラクティス

| 領域                   | ベストプラクティス                                                                          |
| -------------------- | ---------------------------------------------------------------------------------- |
| **Audit Policy**     | *`Stage=RequestResponse` を高感度 API に限定し、残りは `Metadata` でノイズ削減*                      |
| **Log Rotation**     | *kube‑apiserver の `--audit-log-maxsize=100` `--audit-log-maxbackup=10` でディスク枯渇を防止* |
| **Centralized Logs** | *Fluent Bit → Loki / Elasticsearch へ JSON 出力し、`verb=exec` などでクエリしやすくする*            |

## 3. Hands‑on ラボ（35 分）

### 3.1 kind クラスタで Audit Log 有効化

> **ファイル構成** (ローカル)
>
> ```
> audit/
> ├─ audit-policy.yaml
> └─ kind-config.yaml
> ```

#### (1) `audit-policy.yaml` — `kubectl exec` を RequestResponse で収集

```yaml
apiVersion: audit.k8s.io/v1
kind: Policy
rules:
  # 1. exec/attach/portforward は詳細捕捉
  - level: RequestResponse
    verbs: ["exec", "attach", "portforward"]
    resources:
      - group: ""
        resources: ["pods/exec", "pods/attach", "pods/portforward"]
  # 2. それ以外はメタデータ
  - level: Metadata
```

#### (2) `kind-config.yaml` — API Server へマウント & 起動引数

```yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
kubeadmConfigPatches:
- |
  kind: ClusterConfiguration
  apiServer:
    extraArgs:
      audit-policy-file: /etc/kubernetes/audit/audit-policy.yaml
      audit-log-path: /var/log/kubernetes/audit.log
      audit-log-maxsize: "100"
      audit-log-maxbackup: "5"
    extraVolumes:
    - name: audit
      hostPath: /etc/kubernetes/audit
      mountPath: /etc/kubernetes/audit
      readOnly: true
nodes:
- role: control-plane
  extraMounts:
  - hostPath: ./audit
    containerPath: /etc/kubernetes/audit
```

```bash
kind create cluster --config audit/kind-config.yaml
```

### 3.2 `kubectl exec` を発生させログ確認

```bash
# 1) テスト Pod
kubectl run alpine --image=alpine --command -- sleep 600

# 2) exec 実行
kubectl exec alpine -- cat /etc/os-release

# 3) Log 確認 (コンテナ内)
CONTROL_PLANE=$(docker ps --filter label=io.x-k8s.kind.role=control-plane -q)
docker exec $CONTROL_PLANE grep "verb=\"exec\"" /var/log/kubernetes/audit.log | head -1 | jq '."
```

> **期待:** `requestURI":"/api/v1/namespaces/default/pods/alpine/exec` が含まれる JSON エントリが出力。

### 3.3 Fluent Bit で中央集約 (Loki 例)

```bash
# 1) Loki & Grafana 共通チャート
helm repo add grafana https://grafana.github.io/helm-charts && helm repo update
helm install loki grafana/loki-stack --namespace logging --create-namespace \
  --set promtail.enabled=false

# 2) Fluent Bit DaemonSet (抜粋)
cat <<'EOF' | kubectl apply -f -
apiVersion: v1
kind: ConfigMap
metadata:
  name: fluent-bit-config
  namespace: logging
# ... (Parser audit JSON → Loki labels)
---
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: fluent-bit
  namespace: logging
spec:
  template:
    spec:
      containers:
      - name: fluent-bit
        image: cr.fluentbit.io/fluent/fluent-bit:2.2
        volumeMounts:
        - name: auditlog
          mountPath: /var/log/kubernetes
      volumes:
      - name: auditlog
        hostPath:
          path: /var/log/kubernetes
EOF
```
