# Network & Encryption 基礎 — NetworkPolicy・TLS・etcd Encryption

> **対象:** CKAD 85 %・Killer.sh 70 % レベルのエンジニアが KCSA 試験対策として押さえる “ネットワーク & 暗号化” の要点
> **キーワード:** NetworkPolicy / TLS 証明書 / EncryptionConfiguration / Calico

---

## 1. フロー図（通信〜暗号化レイヤの俯瞰）

```
┌──────────────┐        mTLS        ┌──────────────┐
│  Client      │ ───────────────▶  │  Ingress TLS  │
└──────────────┘                    └──────────────┘
        ▲                                       │
        │ NetworkPolicy (allow 443)             ▼
┌──────────────┐      Calico eBPF      ┌────────────────┐

└──────────────┘     etcd Encryption    └────────────────┘
```

---

## 2. 1 行ベストプラクティス

| カテゴリ                          | ベストプラクティス                                                         |
| ----------------------------- | ----------------------------------------------------------------- |
| **NetworkPolicy**             | *Namespace で **`default‑deny`** を敷き、必要なポートだけ **whitelist***       |
| **TLS (In‑Transit)**          | *Ingress / Service Mesh は **mTLS**、証明書管理は **cert‑manager** で自動更新* |
| **etcd Encryption (At‑Rest)** | *`EncryptionConfiguration` を適用し **AES‑CBC** キーを定期ローテート*           |

## 3. Hands‑on ラボ（25 分で完走）

### 3.1 Calico で `default‑deny` → 443 だけ許可

```bash
# 0) Calico が未導入なら kind に追加 (v3.28 例)
kubectl apply -f https://docs.projectcalico.org/manifests/calico.yaml

# 1) デモ Namespace & アプリ作成
kubectl create ns app
kubectl run web --image=nginx:1.27 -n app --labels="app=web" --expose --port 443 --overrides='{"spec":{"containers":[{"name":"nginx","image":"nginx:1.27","ports":[{"containerPort":443}]}]}}'

# 2) Namespace 全体を default‑deny
kubectl apply -f - <<'EOF'
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny
  namespace: app
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  - Egress
EOF

# 3) 443 だけ許可
kubectl apply -f - <<'EOF'
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-https
  namespace: app
spec:
  podSelector:
    matchLabels:
      app: web
  ingress:
  - ports:
    - protocol: TCP
      port: 443
EOF

# 4) 動作確認 (busybox → 予期通りブロック/許可)
kubectl run test --rm -i --tty --image=busybox --restart=Never -- sh -c "nc -zv web.app 80; nc -zv web.app 443"
```

### 3.2 簡易 TLS 証明書 & Secret 作成（自己署名例）

```bash
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout tls.key -out tls.crt -subj "/CN=demo.example.com"
kubectl create secret tls demo-tls --cert=tls.crt --key=tls.key -n app
```

> **Tip:** 実運用は `cert-manager` + ACME (Let’s Encrypt) で自動化。

### 3.3 etcd EncryptionConfiguration を適用（kind シングルノード例）

```bash
# 1) AES 256 キー生成
head -c 32 /dev/urandom | base64

# 2) encryption-config.yaml
cat <<'EOF' > encryption-config.yaml
apiVersion: apiserver.config.k8s.io/v1
kind: EncryptionConfiguration
resources:
- resources: ["secrets"]
  providers:
  - aescbc:
      keys:
      - name: key1
        secret: <上で生成した Base64 キー>
  - identity: {}
EOF

# 3) kube‑apiserver 起動パラメータに追加 (kind は extraMount & extraArgs で再作成)
kind delete cluster && kind create cluster --config kind-with-encryption.yaml

# 4) 検証: Secret を作成し etcdctl で平文漏洩が無いか確認
```
