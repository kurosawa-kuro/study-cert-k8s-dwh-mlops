# 4 C's Security Model — ウェブエンジニア向け実践ガイド

> **対象:** ウェブエンジニア（SQLインジェクション等の基礎セキュリティ知識あり）が KCSA 学習を始めるための 4C's モデル
> **目的:** Cloud → Cluster → Container → Code の 4 層を **攻撃者視点** で俯瞰し、各層の責任分担と防御策を理解

---

## 1. 4 層図（攻撃ベクトル視点）

```
┌───────────────────────────────────────────────────────────────┐
│                          Cloud (Provider)                    │
│  ── 攻撃ベクトル: IAM 権限奪取・ネットワーク侵入・データ漏洩        │
│  ── 責任: クラウド事業者 & 組織 SecOps                        │
│  ── 防御策: IAM最小権限・VPC分離・CloudTrail監査              │
└───────────────────────────────────────────────────────────────┘
┌───────────────────────────────────────────────────────────────┐
│                        Cluster (Platform)                    │
│  ── 攻撃ベクトル: API Server攻撃・etcd侵入・RBAC権限昇格        │
│  ── 責任: プラットフォームチーム / SRE                        │
│  ── 防御策: RBAC最小権限・Audit Policy・NetworkPolicy         │
└───────────────────────────────────────────────────────────────┘
┌───────────────────────────────────────────────────────────────┐
│                       Container (Runtime)                    │
│  ── 攻撃ベクトル: 特権コンテナ・イメージ改ざん・ランタイム脱獄      │
│  ── 責任: DevOps / アプリ所有チーム                          │
│  ── 防御策: PodSecurity・イメージ署名・seccomp/AppArmor       │
└───────────────────────────────────────────────────────────────┘
┌───────────────────────────────────────────────────────────────┐
│                           Code (App)                         │
│  ── 攻撃ベクトル: SQLインジェクション・XSS・Secrets直書き        │
│  ── 責任: 開発チーム                                         │
│  ── 防御策: 入力検証・出力エスケープ・Secrets管理              │
└───────────────────────────────────────────────────────────────┘
```

## 2. ウェブエンジニア向けベストプラクティス（各層 1 行まとめ）

| 層             | 1 行ベストプラクティス                                                    | ウェブエンジニアとの関連性                                    |
| ------------- | --------------------------------------------------------------- | ----------------------------------------------- |
| **Cloud**     | *IAM ロール境界を最小化し、CSPM (Cloud Security Posture Management) を継続監査* | クラウドDB接続時のIAM認証・S3バケットアクセス制御に類似        |
| **Cluster**   | *RBAC 最小権限 + Audit Policy で操作を常時記録*                             | Webアプリのログイン認証・アクセスログ記録に類似              |
| **Container** | *cosign 署名済みイメージを rootless & read‑only で実行*                     | アプリケーションの実行権限制限・ファイル読み取り専用に類似      |
| **Code**      | *依存ライブラリをピン留めし、SCA / SAST を CI で自動スキャン*                         | npm audit・ESLint・OWASP ZAP スキャンに類似              |

---

## 3. 境界と責任分担メモ（実践例）

* **Cloud → Cluster**: VPC／Subnet／Firewall は Cloud 層で定義し、クラスター側では NetworkPolicy で補強。
  * *例: AWS RDS のセキュリティグループ設定 + アプリのDB接続制限*
* **Cluster → Container**: API‑server から RBAC で許可された操作のみがコンテナに届く。
  * *例: Webアプリのセッション管理 + ユーザー権限による機能制限*
* **Container → Code**: コンテナ runtime が制御する領域外でアプリ自身が凡ミス（Secrets 直書き等）しないよう CI で SAST。
  * *例: .env ファイルの環境変数管理 + アプリ内でのSecrets参照*

> 🔍 **使い方**: 印刷または PDF にしてデスク横に貼り、設計レビューや Incident Response Runbook 作成時に参照してください。
