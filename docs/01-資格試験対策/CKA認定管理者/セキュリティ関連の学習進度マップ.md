各認定試験における「Admin（管理）機能」の「基礎知識」→「調査・実装」の関係性を整理します。

## Admin機能の学習進度マップ

### **KCNA (エントリーレベル)**
**基礎知識：** Kubernetesの管理概念の存在を知る
**調査・実装：** 概念レベルのみ
- 「管理者が存在する」ことを理解
- クラスター、ノード、Podという階層があることを知る
- **実装：なし**

### **KCSA (セキュリティ基礎)**
**基礎知識：** セキュリティ管理の責任範囲
**調査・実装：** セキュリティ管理設計の判断
- RBAC、認証・認可の概念理解
- 管理者権限分離の重要性理解
- **実装：理論設計のみ、コマンド操作なし**

### **CKAD (開発者視点)**
**基礎知識：** 開発者に必要な最小限の管理知識
**調査・実装：** 開発環境での限定的な管理操作
```bash
# 開発者レベルの管理操作
kubectl get pods -n my-namespace
kubectl describe deployment my-app
kubectl logs my-pod
```
- **自分のアプリケーション範囲内での管理**
- NamespaceやResourceQuotaの理解
- **クラスター全体の管理権限はなし**

### **CKA (運用管理者視点)**
**基礎知識：** クラスター全体の管理知識
**調査・実装：** 本格的なクラスター管理実装
```bash
# クラスター管理の実装
kubectl drain node-1
kubeadm upgrade plan
kubectl create namespace production
kubectl apply -f rbac-config.yaml
etcdctl snapshot save backup.db
```
- **ノード管理、アップグレード、バックアップ**
- **ユーザー・権限管理**
- **リソース管理、監視設定**

### **CKS (セキュリティ専門家)**
**基礎知識：** CKA + セキュリティ強化管理
**調査・実装：** セキュリティ観点での高度な管理実装
```bash
# セキュリティ強化管理
kubectl-bench run --targets node,master
kube-hunter --remote cluster-ip
falco --config /etc/falco/falco.yaml
kubectl apply -f pod-security-policy.yaml
```

## Admin機能の段階的発展

### **権限レベルの進化**
- **KCNA/KCSA:** 管理概念の理解のみ
- **CKAD:** 限定的な管理（自分のアプリ範囲）
- **CKA:** フルクラスター管理権限
- **CKS:** セキュリティ強化された管理

### **管理対象の拡大**
- **CKAD:** Pod、Deployment、Service
- **CKA:** Node、Cluster、etcd、ユーザー管理
- **CKS:** + セキュリティポリシー、監査、侵入検知

### **トラブルシューティング能力**
- **CKAD:** アプリケーションレベルのデバッグ
- **CKA:** クラスターレベルの障害対応
- **CKS:** + セキュリティインシデント対応

## CKADから見たAdmin機能の学習パス

**あなたの現在地（CKAD）：**
- Pod/Deploymentの基本管理 → ✓
- ログ確認、デバッグ → ✓
- Namespace理解 → ✓

**CKAに向けて必要：**
1. **ノード管理** (drain、cordon、uncordon)
2. **クラスター管理** (kubeadm、etcd)
3. **ユーザー・RBAC管理**
4. **システムレベルトラブルシューティング**

CKADの管理知識は開発者視点での基礎となり、CKAで本格的なクラスター管理者能力に発展させる流れです。
