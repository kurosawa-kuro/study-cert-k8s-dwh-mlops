## 学習手順

### 1. Cosignによるイメージ署名

#### 1.1 Cosignのインストール
```bash
# Cosignインストール
curl -O -L "https://github.com/sigstore/cosign/releases/latest/download/cosign-linux-amd64"
sudo mv cosign-linux-amd64 /usr/local/bin/cosign
sudo chmod +x /usr/local/bin/cosign
```

#### 1.2 キーペアの生成
```bash
# キーペアの生成
cosign generate-key-pair

# 環境変数の設定
export COSIGN_PRIVATE_KEY=cosign.key
export COSIGN_PUBLIC_KEY=cosign.pub
```

#### 1.3 イメージの署名
```bash
# Dockerイメージのビルド
docker build -t myregistry/myapp:v1.0 .

# イメージの署名
cosign sign --key cosign.key myregistry/myapp:v1.0

# 署名の確認
cosign verify --key cosign.pub myregistry/myapp:v1.0
```

### 2. Keyless署名（Fulcio + Rekor）

#### 2.1 Keyless署名の実行
```bash
# Keyless署名（GitHubアカウント認証）
cosign sign myregistry/myapp:v1.0

# Keyless署名の検証
cosign verify myregistry/myapp:v1.0 \
  --certificate-identity=user@example.com \
  --certificate-oidc-issuer=https://github.com/login/oauth
```

#### 2.2 Rekorログの確認
```bash
# Rekorログの検索
rekor-cli search --artifact myregistry/myapp:v1.0

# 署名エントリの詳細確認
rekor-cli get --uuid <uuid>
```

### 3. Policy Controller（旧Admission Controller）

#### 3.1 Policy Controllerの設定
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: cosign-policy
  namespace: cosign-system
data:
  policy.yaml: |
    apiVersion: v1alpha1
    kind: Policy
    metadata:
      name: image-policy
    spec:
      images:
      - glob: "myregistry/myapp:*"
        keyless:
          url: https://fulcio.sigstore.dev
          identities:
          - issuer: https://github.com/login/oauth
            subject: user@example.com
```

#### 3.2 Admission Controllerの設定
```yaml
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingAdmissionWebhook
metadata:
  name: policy.sigstore.dev
webhooks:
- name: policy.sigstore.dev
  clientConfig:
    service:
      name: webhook
      namespace: cosign-system
      path: /validate
  rules:
  - operations: ["CREATE", "UPDATE"]
    apiGroups: [""]
    apiVersions: ["v1"]
    resources: ["pods"]
  admissionReviewVersions: ["v1", "v1beta1"]
```

### 4. Trivyによる脆弱性スキャン

#### 4.1 Trivyのインストール
```bash
# Trivyインストール
sudo apt-get install wget apt-transport-https gnupg lsb-release
wget -qO - https://aquasecurity.github.io/trivy-repo/deb/public.key | sudo apt-key add -
echo "deb https://aquasecurity.github.io/trivy-repo/deb $(lsb_release -sc) main" | sudo tee -a /etc/apt/sources.list.d/trivy.list
sudo apt-get update
sudo apt-get install trivy
```

#### 4.2 イメージスキャン
```bash
# 基本的なスキャン
trivy image myregistry/myapp:v1.0

# 高・中レベルの脆弱性のみ表示
trivy image --severity HIGH,CRITICAL myregistry/myapp:v1.0

# JSON形式での出力
trivy image --format json myregistry/myapp:v1.0 > scan-results.json
```

#### 4.3 Kubernetes統合
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: trivy-config
data:
  trivy.yaml: |
    severity: HIGH,CRITICAL
    ignore-unfixed: true
    format: json
    output: /tmp/scan-results.json
```

### 5. Notary v2による署名検証

#### 5.1 Notary v2のセットアップ
```bash
# Notary v2 CLI インストール
curl -Lo notation https://github.com/notaryproject/notation/releases/download/v1.0.0/notation_1.0.0_linux_amd64.tar.gz
tar -xzf notation_1.0.0_linux_amd64.tar.gz
sudo mv notation /usr/local/bin/
```

#### 5.2 署名の作成と検証
```bash
# 証明書の生成
notation cert generate-test --default "test-cert"

# イメージの署名
notation sign myregistry/myapp:v1.0

# 署名の検証
notation verify myregistry/myapp:v1.0
```

## 検証コマンド

```bash
# Cosign署名の確認
cosign verify --key cosign.pub myregistry/myapp:v1.0

# Trivy脆弱性スキャン
trivy image --severity HIGH,CRITICAL myregistry/myapp:v1.0

# 署名情報の詳細確認
cosign tree myregistry/myapp:v1.0

# SBOMの生成と署名
cosign attest --predicate sbom.json --key cosign.key myregistry/myapp:v1.0
```

## セキュリティベストプラクティス

### 1. 最小特権の原則
```yaml
apiVersion: v1
kind: Pod
spec:
  containers:
  - name: myapp
    image: myregistry/myapp:v1.0
    securityContext:
      runAsNonRoot: true
      runAsUser: 1000
      readOnlyRootFilesystem: true
      allowPrivilegeEscalation: false
      capabilities:
        drop:
        - ALL
```

### 2. 信頼できるレジストリの使用
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: registries-config
data:
  registries.yaml: |
    default:
      - registry: myregistry.example.com
        trust: enabled
    blocked:
      - registry: untrusted-registry.com
```
