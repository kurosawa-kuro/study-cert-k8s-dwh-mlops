### 使い方のヒント

|試験テクニック|概要|
|---|---|
|**`kubectl create -o yaml --dry-run=client`**|ベース YAML を瞬時に生成し `> file.yaml` で保存|
|**マニフェストの最小化**|出題要件の属性以外は削除可（labels や resourceVersion など）|
|**`k explain <kind>.<field>`**|フィールド位置が不明な場合は explain で即確認|
|**`kubectl replace --force -f`**|既存オブジェクト全面置換が最速のケースもある|

## どの問題から取り組むべきか

1. **ConfigMap/Secret・Ingress・PVC** → 実案件でも頻度が高く CKAD 得点源
    
2. **Affinity / Anti‑Affinity / Priority** → 範囲が広いが出題率は高め、理解すると差が付く
    
3. **RollingUpdate / RBAC** → 制約条件が多いため手順を決め打ちしておくことが時短の鍵
    
4. **Ephemeral Containers** → 新しめだが “デバッグ” セクションで狙われやすい
