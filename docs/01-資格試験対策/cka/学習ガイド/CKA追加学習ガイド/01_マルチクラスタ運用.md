# 01_マルチクラスタ運用

## CKAD合格者向け マルチクラスタ運用理解ガイド

### 視点の転換

| 観点 | CKADでの理解 | CKAでの追加理解 |
|------|--------------|----------------|
| クラスタ操作 | 単一クラスタでのアプリケーション管理 | 複数クラスタの統合管理と切り替え |
| コンテキスト | kubectl contextの基本操作 | マルチクラスタでのコンテキスト戦略 |
| 可用性 | Pod/Deploymentレベルの可用性 | クラスタレベルの可用性と災害復旧 |
| リソース管理 | 単一クラスタ内でのリソース制限 | クラスタ間のリソース配分と最適化 |

### 重点学習内容

| CKAD では触れない部分 | CKA での理解 |
|---------------------|-------------|
| クラスタフェデレーション | 複数クラスタを統合管理する仕組みと利点 |
| クロスクラスタネットワーキング | クラスタ間通信の設計と実装 |
| マルチクラスタレプリケーション | アプリケーションのクラスタ間同期 |
| 統合モニタリング | 複数クラスタの一元的な監視体制 |

### 学習目的

1. **複数クラスタの管理手法を理解する**
   - kubeconfig の高度な設定と管理
   - コンテキストの効率的な切り替え
   - クラスタ間の認証・認可の統合

2. **マルチクラスタアーキテクチャの設計原則を学ぶ**
   - Active-Active vs Active-Passive 構成
   - 地理的分散による可用性向上
   - コスト最適化とパフォーマンスのバランス

3. **災害復旧（DR）戦略を理解する**
   - クラスタ間でのバックアップ・リストア
   - フェイルオーバーとフェイルバックの手順
   - RPO/RTO の設計と実装

### 学習手順

#### 1. kubeconfig の高度な管理

```bash
# 複数クラスタの設定を統合
export KUBECONFIG=~/.kube/config-prod:~/.kube/config-dev:~/.kube/config-staging

# マージされた設定を確認
kubectl config view --flatten

# 永続的な統合設定の作成
kubectl config view --flatten > ~/.kube/config-merged
```

#### 2. コンテキストの効率的な管理

```bash
# 全コンテキストの一覧表示
kubectl config get-contexts

# コンテキストの切り替え
kubectl config use-context prod-cluster

# 名前空間も含めたコンテキストの作成
kubectl config set-context dev-ns --cluster=dev-cluster --user=dev-user --namespace=development
```

#### 3. クラスタ間でのリソース同期

```yaml
# クラスタ間同期のためのサンプル設定
apiVersion: v1
kind: ConfigMap
metadata:
  name: cluster-sync-config
  namespace: kube-system
data:
  clusters: |
    - name: prod-primary
      endpoint: https://prod-1.example.com
      region: us-east-1
    - name: prod-secondary
      endpoint: https://prod-2.example.com
      region: us-west-2
  sync-interval: "300"
  sync-namespaces: "production,staging"
```

### 演習アイデア

#### 演習1: マルチクラスタ環境の構築

1. 3つの Kind/Minikube クラスタを作成
2. 各クラスタに異なるアプリケーションをデプロイ
3. 統合 kubeconfig を作成し、シームレスに切り替え

```bash
# クラスタ作成スクリプト例
for cluster in prod dev staging; do
  kind create cluster --name $cluster
  kubectl create namespace app-$cluster
done
```

#### 演習2: クロスクラスタサービス検出

1. Service Mesh（Istio/Linkerd）を使用したマルチクラスタ設定
2. クラスタ間でのサービス通信の確立
3. トラフィック分散とフェイルオーバーのテスト

#### 演習3: 災害復旧シミュレーション

1. プライマリクラスタでのアプリケーション稼働
2. Velero を使用したバックアップ作成
3. セカンダリクラスタへのリストアと切り替え

### CKA試験での出題パターン

| パターン | 問題例 | 対策 |
|---------|--------|------|
| コンテキスト切り替え | 「cluster-2 のコンテキストに切り替えて作業を実行」 | kubectl config use-context の習熟 |
| kubeconfig 管理 | 「新しいクラスタ情報を既存の kubeconfig に追加」 | kubectl config set-cluster/set-credentials の理解 |
| クラスタ間通信 | 「2つのクラスタ間でサービスを公開」 | Service の ExternalName タイプや Ingress の活用 |

### CKAD経験者が陥りがちな誤解

| 誤解 | 正しい理解 |
|------|-----------|
| 「kubectl だけでマルチクラスタ管理は完結する」 | 専用ツール（Rancher、ArgoCD等）との組み合わせが実践的 |
| 「全クラスタで同じ設定を使えばよい」 | 環境ごとの要件に応じた個別最適化が必要 |
| 「フェデレーションは標準機能」 | Kubernetes Federation v2 は別プロジェクト、慎重な導入検討が必要 |

### 学習優先順位

| 優先度 | 項目 | 理由 |
|--------|------|------|
| 高 | kubeconfig の管理とコンテキスト切り替え | CKA試験で頻出、実務でも必須 |
| 高 | クラスタ間のネットワーク設計 | アーキテクチャ理解の基礎 |
| 中 | バックアップ・リストア手順 | 災害復旧の基本スキル |
| 低 | Service Mesh によるマルチクラスタ | 高度なトピック、基礎習得後に学習 |
