### CKAD 経験者が **KCNA-JP** に向けて “追加で重点学習すべき” テーマ

> *CKAD で既に習得済みの **Pod／Deployment／Service／ConfigMap/Secret** などは割愛し、
> KCNA で新たに登場・広がりを持たせたい領域だけを **理解が積み上がる順** に並べています。*

| 学習フェーズ | 重点テーマ                           | 押さえるポイント                                                                           | ゴールチェック例                                           |
| ------ | ------------------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------- |
| **1**  | **クラスタ内部アーキテクチャ**               | API Server → etcd → Scheduler / Controller Manager / kubelet / kube-proxy の役割と通信経路 | 「Pod 作成リクエストが etcd に書かれてから Node に反映されるまで」をフロー図で描ける |
| **2**  | **コンテナ & OCI 基礎**               | コンテナ vs VM、image layer・registry・OCI Runtime (runc/crun)                            | `docker history` を見て「イメージレイヤがキャッシュされる理由」を説明        |
| **3**  | **CNCF Landscape の全体俯瞰**        | カテゴリー（CI/CD・Observability・Service Mesh・Storage …）と代表 OSS 名                         | 主要 OSS をマトリクス図に配置して口頭説明できる                         |
| **4**  | **Observability 三本柱**           | メトリクス（Prometheus）／ログ（Fluent Bit）／トレース（OpenTelemetry）                               | “メトリクス:時系列、ログ:イベント、トレース:スパン” を対比で定義                |
| **5**  | **GitOps & CI/CD 基礎**           | GitOps 原則・Argo CD / Flux の役割、CI→CD 切り分け                                            | `git push` → 自動 Sync→Pod 更新のパイプライン図が描ける            |
| **6**  | **4 C’s セキュリティモデル**             | Cloud / Cluster / Container / Code の脅威と対策                                          | 各レイヤで 1 つずつベストプラクティスを挙げられる                         |
| **7**  | **ネットワーキング & CNI 概要**           | CNI プラグイン概念、Pod–Pod・Pod–Service 通信パス、IngressController vs ServiceLB                | “IP-per-Pod” のメリットを 1 文で説明                         |
| **8**  | **ストレージ & CSI 概要**              | CSI ドライバ、PVC/PV と外部ストレージのマッピング                                                     | 永続ボリュームを動的プロビジョンする流れを図示                            |
| **9**  | **Kubernetes コミュニティ / バージョン管理** | SIG・KEP・リリースサイクル、LTS の概念                                                           | “SIG-Appsは何を担当？”を即答できる                             |
| **10** | **模試で仕上げ**                      | 日本語模試 5 回分を 70 % 以上                                                                | 3 回連続で 70 %↑ を確認したら受験予約                            |

---

#### 学習のコツ

1. **ドキュメント主導で**
   各フェーズの公式ページ（kubernetes.io、prometheus.io、opentelemetry.io 等）をブックマーク → 試験中の検索手順を事前に体に覚え込ませる。
2. **図解アウトプット**
   “A4 1 枚ホワイトボード” を作りながら学ぶと、Landscape やデータフローが一発で思い出せる。
3. **CKAD で使ったマニフェストを題材に**
   例：既存 Deployment に **Prometheus annotation** を足し、ServiceMonitor でスクレイプ体験 → Observability フェーズを実際に手を動かす。

この順番で進めれば **CKAD で培った YAML/CLI スキル** を活かしつつ、
KCNA が評価する “広く浅いクラウドネイティブ知識” を効率よく補完できます。
