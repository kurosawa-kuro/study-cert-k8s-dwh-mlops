### `4cs-security-model.md` — Cloud-Native 4 C’s Security Deep-Dive

*Cloud → Cluster → Container → Code の“四重防御”を試験／実務視点で整理。
KCSA／CKS 学習、SRE / DevOps チーム設計レビュー用のリファレンスに。*

---

## 0. Bird-Eye View — 4 C’s 階層と責任境界

```
┌──────────────────────────────────────┐
│  ☁️  Cloud / Infra (IaaS)            │― CSP, SRE
│     ─ IAM, Network Seg, KMS, Audit   │
├──────────────────────────────────────┤
│  🏢 Cluster (K8s Control + Nodes)    │― Platform / Ops
│     ─ RBAC, PodSecurity, etcd TLS    │
├──────────────────────────────────────┤
│  📦 Container (Runtime & Image)      │― DevSecOps / SecOps
│     ─ Image Scan, Sandboxed Runtime  │
├──────────────────────────────────────┤
│  👨‍💻 Code (App & Dependencies)        │― Dev / AppSec
│     ─ SCA, SAST, SBOM, Secrets Mgmt   │
└──────────────────────────────────────┘
```

---

## 1. Cloud / Infrastructure Layer (☁️)

| 項目                       | 実務ベストプラクティス                                      | CLI / Hands-on Check                         |
| ------------------------ | ------------------------------------------------ | -------------------------------------------- |
| **IAM & KMS**            | Least-Privilege IAM、KMS で etcd & PV 暗号化          | `aws iam get-user`<br>`aws kms describe-key` |
| **Network Segmentation** | VPC per env、Subnet FW rules、Private API Endpoint | `aws ec2 describe-security-groups`           |
| **Audit & Config Mgmt**  | AWS Config / GuardDuty / CloudTrail → SIEM       | `aws logs describe-log-groups`               |

> **試験ポイント** (KCSA/CKS): *「etcd at-rest encryption requires KMS provider」* を即答できる。

---

## 2. Cluster Layer (🏢)

| 項目                 | 説明                                                        | 試験ワード                                           |
| ------------------ | --------------------------------------------------------- | ----------------------------------------------- |
| **RBAC & OIDC**    | `ClusterRole → RoleBinding`、OIDC provider 連携              | `kubectl auth can-i`                            |
| **Pod Security**   | PodSecurity Standards (baseline/restricted) or PSP→PSS    | `pod-security.kubernetes.io/enforce=restricted` |
| **etcd Hardening** | TLS, `--peer-cert-allowed-cn`, encryptionConfig           | `kube-apiserver --encryption-provider-config`   |
| **Node Hardening** | `kubelet --read-only-port=0`, `--protect-kernel-defaults` | CKS「System Hardening」                           |

---

## 3. Container Layer (📦)

| 項目                    | 実践策                                                    | 代表 OSS                              |
| --------------------- | ------------------------------------------------------ | ----------------------------------- |
| **Image Hygiene**     | Multi-stage build, Remove package manager, Cosign sign | Trivy, Grype                        |
| **Runtime Isolation** | Seccomp, AppArmor, rootless, gVisor/Kata               | Falco, Kube-bencher                 |
| **Supply Chain**      | SBOM (syft), in-toto provenance, Policy Admission      | Kyverno, SigStore Policy-Controller |

---

## 4. Code Layer (👨‍💻)

| 項目                  | 具体アクション                                             | Tool                    |
| ------------------- | --------------------------------------------------- | ----------------------- |
| **Secrets Mgmt**    | `.env` 禁止 → External Secrets Operator / Vault Agent | ESO, HashiCorp Vault    |
| **Static Analysis** | SAST, License Scan (FOSSA)                          | SonarQube, Snyk Code    |
| **Dependencies**    | Pin versions, Renovate bot, CVE alert               | Dependabot, OSV-Scanner |

> **気付き**― Code レイヤの脆弱性が **Container** → **Cluster** にエスカレートする。
> 例: Log4Shell → RCE → root user → Privileged Pod → Node 乗っ取り。

---

## 5. Drill-Down Matrix — 攻撃パスと防御策

| Entry Vector         | Escalation Path            | 4 C’s バリア                | 代表対策                                            |
| -------------------- | -------------------------- | ------------------------ | ----------------------------------------------- |
| Compromised CI Token | Push malicious image → Pod | **Container**            | Image Signature Verification (Cosign + Kyverno) |
| Mis-config SG        | Exposed API Server         | **Cloud**                | VPC PrivateLink, Security Group least priv.     |
| Privileged Pod       | Host Namespace Escape      | **Cluster**              | `restricted` PSS, Seccomp default               |
| Vulnerable Library   | RCE in app                 | **Code** → **Container** | SAST + Runtime WAF                              |

## 6. 学習ハンズオン — 40 分クイックラボ

1. **Enable PSS:**

   ```bash
   kubectl label ns dev pod-security.kubernetes.io/enforce=baseline
   kubectl run evil --image=ubuntu -- sh -c 'sleep 1h'
   # → gets blocked
   ```
2. **Sign & Verify Image:**

   ```bash
   cosign sign --key cosign.key myrepo/app:v1
   kyverno apply verify-image.yaml
   ```
3. **Falco Rule Trigger:**

   ```bash
   kubectl exec evil -- bash -c 'touch /bin/sh'   # Falco alert!
   ```

## 8. まとめ

* **“城壁構造”**：外側（Cloud）で守り切れなくても内側（Cluster/Container/Code）で塞ぐ“Defense-in-Depth”。
* **設計レビュー**では **「この対策はどの C を守っているか？」** を意識。
* 実装→監査→アラートまで **OSS パイプライン化**（Trivy+Kyverno+Prom+Falco）すると CKS 実技でも威力を発揮。
