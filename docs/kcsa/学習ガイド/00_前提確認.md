# k8s コア概念セキュリティ復習ガイド（KCSA 0. 前提確認）

CKAD で培った基礎を **Security 視点** で再確認し、KCSA 学習をスムーズに進めるためのコンパクト教材です。

> **対象:** ウェブエンジニア（SQLインジェクション等の基礎セキュリティ知識あり）
> **目標:** k8s リソースを **攻撃者視点** で理解し、防御策を即座に想起できる

---

## 1. 学習ゴール

* 各リソースの **攻撃ベクトル** を 3 分以内で説明できる
* 最小構成の **セキュリティ検証コマンド** を暗記し、実機で即実行できる
* `kubectl auth can-i` を使った **権限可視化** と **トラブルシュート** が習慣化している

---

## 2. クイック表（セキュリティ観点まとめ）

| リソース                   | 攻撃ベクトル                    | 防御策                                                | 検証コマンド                                           |
| ---------------------- | --------------------------- | --------------------------------------------------- | ------------------------------------------------ |
| **Pod**                | 特権コンテナ・ホストマウント・リソース枯渇       | `securityContext`, requests/limits, readOnlyRootFS | `kubectl get pod -o yaml \| grep -A5 securityContext` |
| **Deployment**         | 古いイメージ・過剰権限・サージ攻撃            | ImagePullPolicy, maxUnavailable, サージ制御              | `kubectl rollout history deployment/nginx`           |
| **Service**            | 不要な公開・ポートスキャン・DNS攻撃           | タイプ別の公開範囲、NetworkPolicy との併用                       | `kubectl get svc -o wide`                           |
| **RBAC**               | 過剰権限・権限昇格・サービスアカウント悪用        | 最小権限原則、Impersonation、Aggregated CR                 | `kubectl auth can-i --list --as system:serviceaccount:...` |
| **kubectl auth can-i** | 権限テスト                 | 失敗原因切り分け、CI での権限テスト                                | `kubectl auth can-i create pods -n dev`               |

## 3. Hands‑on スクリプト（10 分で完走）

> **前提:** kind または minikube でクラスタ起動済み

### 3.1 セキュリティ観点での Pod → Deployment → Service

```bash
# Pod を単発で起動し セキュリティ設定を観察
kubectl run demo-pod --image=nginx:1.25 --restart=Never
kubectl get pod demo-pod -o yaml | grep -A10 -B5 securityContext

# Deployment を作り セキュリティ設定を追加
kubectl create deployment demo --image=nginx:1.25 --replicas=2
kubectl patch deployment demo -p '{"spec":{"template":{"spec":{"securityContext":{"runAsNonRoot":true,"runAsUser":1000}}}}}'

# Service で公開して ネットワークアクセスを確認
kubectl expose deployment demo --port 80 --type ClusterIP
kubectl get svc demo -o yaml | grep -A5 -B5 type
```

### 3.2 RBAC 最小権限 & 権限チェック（攻撃者視点）

```bash
# 名前空間と ServiceAccount
kubectl create namespace dev
kubectl create sa reader -n dev

# Pod 読み取り専用 Role と Binding
kubectl create role pod-reader --verb=get,list,watch --resource=pods -n dev
kubectl create rolebinding pod-reader-binding --role=pod-reader --serviceaccount=dev:reader -n dev

# 権限確認（攻撃者が試行する操作）
kubectl auth can-i get pods --as system:serviceaccount:dev:reader -n dev        # -> yes
kubectl auth can-i delete pods --as system:serviceaccount:dev:reader -n dev     # -> no
kubectl auth can-i get secrets --as system:serviceaccount:dev:reader -n dev     # -> no

# すべての権限を一覧表示（権限エスカレーションの可能性を確認）
kubectl auth can-i --list --as system:serviceaccount:dev:reader -n dev | grep -E "(create|delete|update|patch)"
```

## 4. チェックリスト ✅ / ❌

* [ ] Pod の **攻撃ベクトル** を 3 つ列挙できる（特権コンテナ、ホストマウント、リソース枯渇）
* [ ] Deployment の **セキュリティ設定** を 2 つ説明できる（securityContext、ImagePullPolicy）
* [ ] Service の **ネットワークリスク** を理解している（不要な公開、ポートスキャン）
* [ ] RBAC の **権限昇格リスク** を説明できる（過剰権限、サービスアカウント悪用）
* [ ] `kubectl auth can-i` で **攻撃者の権限確認** ができる

> **活用法:** プルリクやトラブル対応時に **攻撃ベクトル & 防御策** を即参照して、Security 視点の抜け漏れを防止！
