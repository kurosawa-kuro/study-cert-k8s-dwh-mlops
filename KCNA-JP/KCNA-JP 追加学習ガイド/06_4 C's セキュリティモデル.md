## 2. 4 C's セキュリティモデルの意義（KCNA 重点）

### 2-1. なぜ4つの階層なのか？

**CKAD では習得済み**：
- 基本的な RBAC 設定
- Secret の管理
- 個別セキュリティ機能

**KCNA で追加理解**：
- **多層防御**の重要性
- **責任分離**の原則
- **攻撃ベクトル**の多様性

### 2-2. 4つの階層の役割

| 階層 | 範囲 | KCNA での理解 |
|------|------|---------------|
| **Cloud** | インフラ・クラウドサービス | 「基盤レベルのセキュリティ」 |
| **Cluster** | Kubernetes クラスタ | 「オーケストレーションレベルのセキュリティ」 |
| **Container** | コンテナ・ランタイム | 「実行環境レベルのセキュリティ」 |
| **Code** | アプリケーション・コード | 「アプリケーションレベルのセキュリティ」 |

---

## 3. Cloud 階層の理解

### 3-1. Cloud 階層の責任範囲

| 要素 | セキュリティ対策 | KCNA での理解 |
|------|-----------------|---------------|
| **IAM** | 最小権限の原則<br>ロールベースアクセス | 「認証・認可の基盤」 |
| **ネットワーク** | VPC・セキュリティグループ<br>プライベートサブネット | 「ネットワーク分離」 |
| **暗号化** | KMS・ストレージ暗号化<br>転送時暗号化 | 「データ保護」 |

### 3-2. Cloud 階層の重要性

**KCNA で問われるポイント**：
- **基盤の保護** ― クラウドリソースのセキュリティ
- **ネットワークセキュリティ** ― 通信経路の保護
- **データ保護** ― 保存時・転送時の暗号化

---

## 4. Cluster 階層の理解

### 4-1. Cluster 階層の責任範囲

| 要素 | セキュリティ対策 | KCNA での理解 |
|------|-----------------|---------------|
| **RBAC** | ロール・ロールバインディング<br>最小権限の付与 | 「クラスタ内アクセス制御」 |
| **Pod Security** | Pod Security Standards<br>セキュリティコンテキスト | 「Pod レベルのセキュリティ」 |
| **Network Policy** | ネットワークポリシー<br>Pod 間通信制御 | 「ネットワーク分離」 |

### 4-2. Cluster 階層の特徴

**KCNA で問われるポイント**：
- **認証・認可** ― クラスタ内ユーザーの管理
- **Pod セキュリティ** ― コンテナ実行環境の保護
- **ネットワーク制御** ― Pod 間通信の制御

---

## 5. Container 階層の理解

### 5-1. Container 階層の責任範囲

| 要素 | セキュリティ対策 | KCNA での理解 |
|------|-----------------|---------------|
| **イメージセキュリティ** | 脆弱性スキャン<br>署名検証 | 「コンテナイメージの信頼性」 |
| **ランタイム保護** | Seccomp・AppArmor<br>Capabilities 制限 | 「実行時のセキュリティ」 |
| **サプライチェーン** | SBOM・プロビナンス<br>依存関係管理 | 「ソフトウェアの透明性」 |

### 5-2. Container 階層の重要性

**KCNA で問われるポイント**：
- **イメージの信頼性** ― 脆弱性のないイメージ使用
- **実行時保護** ― コンテナの分離・制限
- **サプライチェーンセキュリティ** ― 依存関係の管理

---

## 6. Code 階層の理解

### 6-1. Code 階層の責任範囲

| 要素 | セキュリティ対策 | KCNA での理解 |
|------|-----------------|---------------|
| **アプリケーションセキュリティ** | 入力検証<br>認証・認可 | 「アプリケーションレベルの保護」 |
| **シークレット管理** | 環境変数・Secret<br>外部シークレット管理 | 「機密情報の保護」 |
| **セキュアコーディング** | SAST・DAST<br>コードレビュー | 「開発時のセキュリティ」 |

### 6-2. Code 階層の特徴

**KCNA で問われるポイント**：
- **アプリケーション保護** ― ビジネスロジックのセキュリティ
- **機密情報管理** ― 認証情報・API キーの保護
- **開発プロセス** ― セキュアな開発手法

---

## 7. 4 C's の連携（KCNA 重点）

### 7-1. 多層防御の概念

```
攻撃者
   ↓
Cloud 階層（ネットワーク・IAM）
   ↓
Cluster 階層（RBAC・Pod Security）
   ↓
Container 階層（イメージ・ランタイム）
   ↓
Code 階層（アプリケーション）
```

### 7-2. 責任分離の原則

**KCNA で問われるポイント**：
- **各階層の責任** ― 明確な役割分担
- **相互補完** ― 階層間の連携
- **Defense in Depth** ― 多層防御戦略

---

## 8. KCNA 試験対策 ― 3つの理解レベル

### Level 1: 階層識別
- 「IAM・VPC → Cloud 階層」
- 「RBAC・Pod Security → Cluster 階層」

### Level 2: 責任理解
- 「各階層のセキュリティ責任」
- 「攻撃ベクトルと防御策」

### Level 3: 設計判断
- 「セキュリティ要件 → 適切な階層選択」
- 「多層防御の設計方針」

## 9. CKAD 経験者が陥りがちな誤解

| 誤解 | 正しい理解 |
|------|-----------|
| 「4 C's = 4つの独立した対策」 | 「4 C's = 多層防御の統合戦略」 |
| 「Cluster 階層だけで十分」 | 「全階層の組み合わせが重要」 |
| 「Code 階層 = 開発者の責任のみ」 | 「Code 階層 = チーム全体の責任」 |

## 10. KCNA 頻出問題パターン

### 10-1. 階層分類
```
Q: Pod Security Standards は4 C's のどの階層に属するか？
A: Cluster 階層（Kubernetes クラスタレベルのセキュリティ）
```

### 10-2. 責任理解
```
Q: コンテナイメージの脆弱性スキャンはどの階層の責任か？
A: Container 階層（コンテナ・ランタイムレベルのセキュリティ）
```

### 10-3. 設計判断
```
Q: 多層防御を実現するための4 C's の活用方法は？
A: 各階層で適切なセキュリティ対策を実装し、相互補完的に防御
```

## 11. 学習の優先順位

### 高優先度（KCNA 必須）
1. **4つの階層の役割** ― Cloud、Cluster、Container、Code
2. **責任分離の原則** ― 各階層のセキュリティ責任
3. **多層防御の概念** ― Defense in Depth

### 中優先度（理解を深める）
1. **攻撃ベクトル** ― 各階層での脅威
2. **防御戦略** ― 階層別の対策方法

### 低優先度（CKAD で習得済み）
1. 個別セキュリティ機能の詳細設定
2. 具体的な実装手順

## 12. セルフチェック（CKAD 経験者向け）

### 理解度確認
1. **4 C's セキュリティモデルの4つの階層は？**
   - Cloud（インフラ・クラウドサービス）
   - Cluster（Kubernetes クラスタ）
   - Container（コンテナ・ランタイム）
   - Code（アプリケーション・コード）

2. **各階層の主なセキュリティ責任は？**
   - Cloud：基盤・ネットワーク・データ保護
   - Cluster：認証・認可・Pod セキュリティ
   - Container：イメージ・ランタイム・サプライチェーン
   - Code：アプリケーション・シークレット・開発プロセス

3. **多層防御の意義は？**
   - 攻撃ベクトルの多様性への対応
   - 単一障害点の回避
   - 包括的なセキュリティ保護

## 13. まとめ

**CKAD から KCNA への学習方針**：
- **個別機能** → **全体戦略** への視点拡大
- **技術実装** → **設計原則** への理解
- **単体対策** → **多層防御** への理解

**KCNA 合格の鍵**：
- 4つの階層の役割と責任を明確に理解
- 多層防御の概念と重要性を把握
- 各階層の相互補完関係を理解
