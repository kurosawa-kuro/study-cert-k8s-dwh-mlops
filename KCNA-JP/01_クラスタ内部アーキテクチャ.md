# 1. クラスタ内部アーキテクチャ ― 深掘りガイド

*対象：CKAD レベルのマニフェスト操作経験があり、
KCNA で「そもそもコントロールプレーンはどう動く？」を体系的に押さえたい人*

---

## 1-1. コントロールプレーン主要コンポーネント

| コンポーネント                                             | 主な責務                                            | 代表的な YAML / CLI 影響点                                |
| --------------------------------------------------- | ----------------------------------------------- | -------------------------------------------------- |
| **API Server (kube-apiserver)**                     | REST 入口・Admission・認証認可・OpenAPI Schema           | `kubectl apply` されたオブジェクトが最初に通る                    |
| **etcd**                                            | 永続キーバリューストア　(宣言的“理想状態”の源)                       | `/registry/<Group>/<Resource>/…` にキー保存             |
| **Scheduler**                                       | **未割り当て Pod** に Node を決定                        | `kubectl describe pod …` に `Events: Scheduled` が付与 |
| **Controller Manager**<br>(kube-controller-manager) | Deployment / RS / Job など全ての “○○Controller” を束ねる | ―                                                  |
| **Cloud-Controller Manager**                        | LB や Volume などクラウド依存リソースを作成                     | EKS では AWS CCM が別 Pod で動作                          |

---

## 1-2. ノード側コンポーネント

| コンポーネント                                   | 主な責務                                     | 重要ログファイル                                       |              |
| ----------------------------------------- | ---------------------------------------- | ---------------------------------------------- | ------------ |
| **kubelet**                               | Node に割り当てられた Pod を CRI 経由で起動／監視         | `/var/log/messages` or `journalctl -u kubelet` |              |
| **Container Runtime (containerd, crio…)** | Pod 内コンテナ起動／停止                           | `/var/log/containerd` など                       |              |
| **kube-proxy**                            | iptables または ipvs で `ClusterIP → Pod` 転送 | \`iptables-save                                | grep KUBE-\` |

---

## 1-3. “Pod 作成リクエスト” フロー図（テキスト版）

```
kubectl apply -f pod.yaml
        │
        ▼
1. kube-apiserver ①認証 → ②Admission → ③etcd へ CRUD
        │
        ▼ WATCH
2. kube-scheduler   (Pending Pod ← .spec.nodeName?)
        │  Patch
        ▼
3. etcd  更新 (nodeName 決定)
        │  WATCH
        ▼
4. kubelet @NodeX  実行 → CRI → Container Runtime → Pod Running
        │
        ▼
5. kube-proxy  Service ルールがあれば iptables/ipvs 反映
```

---

## 1-4. トラブルシュート “3 ステップ”

| ステップ                    | 観察ポイント                                                                                   | 代表コマンド                                                       |                        |              |
| ----------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------ | ---------------------- | ------------ |
| **① API Server / etcd** | `kubectl get events --sort-by=.metadata.creationTimestamp`<br>Pending のまま？ Admission 失敗？ | `bash\nkubectl get --raw /readyz\netcdctl endpoint health\n` |                        |              |
| **② Scheduler**         | `events` に `Successfully assigned` が無い → フィットネス不足                                        | `kubectl describe pod …` で `node(s) had taint` 等             |                        |              |
| **③ Node / kubelet**    | Scheduled 済でも `ContainerCreating → CrashLoopBackOff`                                     | \`\`\`bash\njournalctl -u kubelet                            | tail -50\ncrictl ps -a | head\n\`\`\` |

## 1-5. ハンズオン短期メニュー

1. **Pending 体験**

   ```bash
   # ノードに Taint を付与してスケジューリング失敗を再現
   kubectl taint node $(kubectl get node -o name | head -1) key=value:NoSchedule
   kubectl run test-pod --image nginx
   kubectl describe pod test-pod | grep -A2 ^Events
   ```
2. **etcd キー参照**

   ```bash
   ETCD_POD=$(kubectl -n kube-system get po -l component=etcd -o name)
   kubectl -n kube-system exec $ETCD_POD -- \
     etcdctl get /registry/pods --prefix --keys-only | head
   ```
3. **Service ルール確認**

   ```bash
   iptables-save | grep KUBE-SVC | head
   ```

---

## 1-6. 暗記のコツ

* **「API → etcd → Controller/Scheduler → kubelet」** を **左から右** に矢印で 3 回書く
* “Pending→Scheduled→ContainerCreating→Running” の **フェーズ遷移** を覚え、各段階で**どのコンポーネントが関わるか**を書き込む
* `kubectl get events` の **Timestamp 並び** を眺めて「次の処理は何？」と自問
